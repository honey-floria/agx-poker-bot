# AGX 多人德州扑克：蒸馏与冲榜 TODO

> 目标：针对 AGX「多人德州扑克」常驻比赛，构建一个符合平台资源限制、能够稳定提升天梯排名的六人无限注德州扑克策略。
>
> 核心路线：**公开强手行为克隆 + 自有求解器软标签 + 轻量学生模型 + 当前换座阶段内的对手适应 + 严格安全回退**。

## 0. 已确认的比赛约束

- [x] 将规则版本固定为 `rsi-poker-4.1`，版本变化时停止训练并重新审计。
- [x] 六人无限注现金局，SB/BB = 50/100，无前注。
- [x] 每手所有座位恢复至 10,000 筹码，即 100BB。
- [x] 每局 240 手，分为 6 个换座阶段，每阶段 40 手。
- [x] 每个参赛者最终坐过全部 6 个物理座位。
- [x] 相同的 40 个物理发牌与按钮序列会在 6 个阶段重复。
- [x] 策略上下文在第 1、41、81、121、161、201 手前重新初始化。
- [x] 不依赖跨换座阶段的内存或统计。
- [x] 下注与加注的 `to` 表示本街累计投入，而非额外投入。
- [x] 单次动作上限 0.2 秒，初始化上限 2 秒。
- [x] 每席整局累计 CPU 上限 20 秒。
- [x] JavaScript 源码上限 4,194,304 字节。
- [x] JavaScript 堆上限 128MB，栈上限 1MB。
- [x] 最终按 240 手累计真实筹码净额得到本局名次，再以 OpenSkill 更新天梯。
- [x] 部署策略不得访问网络或外部模型文件。

实现说明：上述冻结值集中保存在 `config/competition.json`。`tools/competition_rules.py`、训练、导出和静态校验采用失败关闭策略；直接提交模拟器在每个 40 手阶段重建策略上下文，并检查初始化、单动作和每席整局累计决策预算。堆与栈上限属于平台运行时限制，本地清单与测试负责防止配置漂移。

## 10. JavaScript 部署与安全层

- [ ] 只使用内嵌查表与权重，不访问网络或文件。
- [ ] 对所有输出先应用合法动作掩码。
- [ ] 对剩余动作概率重新归一化。
- [ ] 将下注桶转换成平台要求的本街累计 `to`。
- [ ] clamp 到 `[minRaiseTo, maxRaiseTo]`。
- [ ] 不能加注时回退到 call/check/fold。
- [ ] 使用确定性状态哈希实现混合频率采样。
- [ ] 哈希包含自己的牌、公共牌、位置、街道和下注状态。
- [ ] 不使用跨阶段状态或隐藏信息。
- [ ] 对缺字段、NaN、非法数组和极端数值建立防御性处理。
- [ ] 任何异常都返回合法被动动作，不抛出异常。
- [ ] 预留至少 25% CPU、源码和内存余量。
- [ ] p99 动作耗时目标低于 10ms。
- [ ] 整局 CPU 目标低于 8–10 秒。
- [ ] 源码目标低于 3.5MB。
- [ ] 10万次动作零异常，1,000局零离场后才允许提交。

提交源码中的 `METHOD` 应如实说明：

```text
Data & training: Distilled offline from publicly accessible completed
match replays, self-generated solver labels, and local self-play.
No private opponent traces or hidden execution data were used.
```

## 12. 离线候选晋级标准

快速筛选：

- [ ] 每个候选至少 200 局，即 48,000 手。
- [ ] 使用完全相同的发牌种子和座位轮换做 paired evaluation。

正式对照：

- [ ] 每个候选至少 2,000 局，即 480,000 手。
- [ ] 按整局 bootstrap 计算 95% 置信区间。

最终确认：

- [ ] 每个候选至少 10,000 局，即 240 万手。
- [ ] 主要指标没有明显退化。
- [ ] 模拟 OpenSkill 增量优于当前正式版本。
- [ ] 平均名次或第一名率至少一项稳定改善。
- [ ] 对主要对手类型不存在严重负收益。
- [ ] 故障率为 0。

候选选择目标：

```text
J = E[OpenSkill 变化]
  + 0.3 * 第一名率
  - 巨额系数 * 故障率
```

`mbb/hand` 是重要诊断指标，但不是唯一目标。
